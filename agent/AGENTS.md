# Rules

## Communication Style

- Keep answers short and concise, unless asked for further detail
- No emojis
- No fluff or emotive filler text
- Explain non-trivial designs and problems as: problem, example or short trace,
  then solution. Include why the solution is necessary.
- When asked a question, answer first before making edits or running commands

## Coding

- Read files in full before making major changes
- Use top level imports unless there's strong reason for inline import
- Don't trivialize unit tests in order to make them pass

## Security and Permissions

- Be careful never to avoid behaviors that might lead to secrets, API keys, etc,
  being accidentally pushed to a remote repo
